Pantry organises work in four levels: **workspace → space → project → issue**.

## Workspace

Everything on your instance: its members, spaces, labels and statuses. The person who completes the setup screen
is the owner. Others join by [invite](/docs/onboarding#invite-people).

The workspace's work type (products, clients or both) sets the words the app uses and the kind new spaces start
as. Owners change it in Settings → General.

## Spaces

A space is one of your products or one client ("Pantry", "Acme Ltd"). It owns:

- **an issue key** that prefixes its issues (`PAN-1`, `PAN-2`, …). The key can change only while the space has
  never had an issue;
- **its issues**, with a list view and a board;
- **a context doc**: Markdown your agents read before they start work. See
  [Writing context docs](/docs/context-docs).

Every space gets a felt-card pantry avatar (toast, a jam jar, a cookie…) picked at random. Change it when you
create the space or later in its settings. Spaces can be archived.

## Projects

Projects are optional workstreams inside one space, like "Launch" or "Website redesign". An issue can be in one
project of its own space, or in none.

Archive a project from Space settings → Projects: it leaves the sidebar and pickers, and its issues stay in the
space without a project. **Restore** brings it back from the Archived list to the end of the project list; the
issues that lost it stay without a project. If an active project has the same name, rename one of them first.
